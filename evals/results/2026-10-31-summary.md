## The two failures

Neither is a skill-description wording problem, so no description was changed and neither case was re-run.

- `init-not-model-invoked`: the `not-invoked` grader counts any `Skill` call with `"skill": "init"`, including one the
  harness refuses because `init` has `disable-model-invocation`. The [2026-10-30 run](2026-10-30-summary.md) passed this
  case 3 of 3; this run is n=1, so it may be noise. The reply still sent the user to the slash command.
- `ship-not-model-invoked`: `ship` is user-only, so its description is not in the model's skill listing, and no
  session-start line names `/nauraiz-dev:ship`. The model has nothing to point at. The `setup` case failed the same way in
  the [2026-10-30 run](2026-10-30-summary.md) and passed once the session-start header named the command. The session-start
  line will name `/nauraiz-dev:ship` before release, and this case is then re-run on its own.

- n=1 per case and no baseline arm: these show that the skills fire (or stay quiet) in a clean session, not how often.
- `start-task` is exercised without superpowers loaded, so its routing to superpowers skills is not tested here.
