The questions row counts AskUserQuestion calls only: headless runs write their questions as decisions in the answer text, and those are not counted. Under `claude -p` a PreToolUse `ask` from a hook is treated as a deny: the edit is refused with the hook's reason and listed in the result's permission denials (probed on Claude Code 2.1.314). Files touched are read from each clone after the run (committed, modified and untracked, repo-relative). Files the setup created or changed are not listed under files touched, so an arm edit to a file the setup also changed is not listed either. The token cap is enforced by the harness, not by a claude flag: it counts weighted tokens (input + output + cache creation + 0.1 x cache read, rounded down) per assistant message from the stream and kills the arm once the count reaches 1500000. Output is estimated while the arm runs, because the stream carries real output totals only in the result line (the characters of the text and tool inputs divided by 4, plus the thinking-token events). A message can overshoot the cap, and the arm keeps its partial stream.
